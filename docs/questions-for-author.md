# Вопросы автору кейса

Проект: система бронирования переговорных комнат. Ответы влияют на модель данных и правила; на время ожидания принято рабочее допущение, проектирование не блокируется.

| # | Вопрос | Допущение пока | Что изменится, если ответ другой | Ответ |
|---|---|---|---|---|
| Q1 | Как устроены помещения: плоский список комнат, «здание → этаж → комната» или несколько офисов в разных городах? | Плоский список, местоположение — текстовое поле | Появятся сущности `building`/`floor`/`office`, фильтры в UI и поиске | |
| Q2 | Часовой пояс организации? Есть ли выходные и праздники, когда бронирование запрещено? | Один пояс `Europe/Moscow`, брони возможны в любой день | Календарь рабочих дней, часовой пояс на уровне офиса, пересчёт загрузки | |
| Q3 | Ожидаемый масштаб: число комнат, пользователей, броней в день? | ~50 комнат, ~500 пользователей | Индексы, пагинация, необходимость кэша | |
| Q4 | Нужно ли согласование брони администратором для отдельных комнат (например, для большого зала)? | Нет, бронь подтверждается сразу | Третий статус `pending`, экран согласования, уведомления | |
| Q5 | Что делать с предстоящими бронями, когда комнату отключают на ремонт? | Брони остаются, администратор отменяет вручную, организатор не уведомляется автоматически | Массовая отмена, уведомления организаторам, предложение альтернативы | |
| Q6 | Должны ли сотрудники видеть статистику по своим броням? | Нет, статистика только у администратора | Отдельный раздел «Моя статистика» | |
| Q7 | Нужен ли отчёт в .docx или .xlsx, кроме CSV? | Нет, только CSV | Генерация файлов в бэкенде | |
| Q8 | Ограничение на число одновременных броней или горизонт бронирования (например, не дальше чем на 3 месяца вперёд)? | Ограничений нет | Правило в бизнес-логике и сообщение об ошибке | |
| Q9 | Может ли сотрудник бронировать «за другого» (например, секретарь для руководителя)? | Нет, организатор — тот, кто создаёт бронь | Поле «на кого бронь», права секретаря | |
| Q10 | Нужно ли фиксировать фактическое использование (пришли на встречу или нет, «no-show»)? | Нет | Отметка о заезде, метрика no-show в статистике, автоосвобождение слота | |
| Q11 | Что обязательно нужно показать на защите или при проверке: какие сценарии, каких форматов отчёт? | Сценарии из критериев приёмки, отчёт по ГОСТ/шаблону вуза | Структура отчёта и презентации | |
| Q12 | Есть ли требования к стеку или запуску (обязательные технологии, ограничения по окружению)? | Свободный выбор, запуск через Docker | Смена технологий, способ поставки | |
